# 📦 팝업스토어 검색 기능 개선 - Elasticsearch 도입기

## 📌 개요

기존 LIKE 기반의 검색 방식은 성능과 정확도 면에서 한계를 가지고 있었습니다. 이를 해결하고 검색 품질을 향상시키기 위해 **Elasticsearch 기반의 전문 검색 시스템**을 도입하였습니다.

---

## 1. ❓ 왜 도입했는가?

기존 RDB 기반 검색에는 다음과 같은 문제가 있었습니다:

- `LIKE '%검색어%'` 방식은 **전체 테이블 스캔**으로 인해 성능 저하
- `"뉴진스"` 검색 시 `"진스"`, `"진스톤"` 같은 **불필요한 결과 포함**
- **검색 정확도와 정렬 기준 미흡** (연관도, 최근성 등 반영 어려움)
- **한글 ↔ 영문 혼용 검색 불가**
- **검색 기능 확장성 부족** (추천, 자동완성, 필터링 등)

---

## 2. 🧠 왜 Elasticsearch인가?

| 항목 | Elasticsearch | 기존 LIKE 검색 |
|------|---------------|----------------|
| 실시간 색인 | ✅ 지원 | ❌ 미지원 |
| 부분 검색 | ✅ 가능 (`n-gram`, `wildcard`) | ❌ |
| 유사도 정렬 | ✅ 스코어 기반 | ❌ |
| 다국어 지원 | ✅ Nori 등 분석기 지원 | ❌ |
| 다중 필드 검색 | ✅ (`multi_match`) | ❌ 복잡 |
| 확장성 (추천, 자동완성 등) | ✅ | ❌ |

Elasticsearch는 **텍스트 검색에 특화된 분산형 검색엔진**으로, 기존 RDB로는 구현이 어려운 다양한 기능을 손쉽게 제공합니다.

---

## 3. ⚡ 도입 전후 성능 비교

| 항목 | 개선 전 (LIKE 검색) | 개선 후 (Elasticsearch) | 개선 효과 |
|------|----------------------|--------------------------|------------|
| 평균 검색 응답 시간 | 300~500ms | 30~50ms | 🔽 약 90% 개선 |
| 초당 처리 요청 수 (QPS) | 30~40 | 400+ | 🔼 10배 이상 |
| 검색 정확도 | 낮음 | 높음 (다중 필드, 유사도 기반 정렬) |
| 다국어 대응 | ❌ | 🔄 일부 (영문 데이터 기준) |
| 정렬/필터 기능 | 제한적 | 동적 정렬 및 다중 조건 필터 |

---

## 4. 🚀 기대 효과 및 향후 계획

### ✅ 현재 효과
- 빠른 검색 속도와 높은 정확도
- 다양한 정렬 조건 (`openDate`, `viewCnt`, `createdAt`) 지원
- 다중 필드 기반 유연한 검색 (`name`, `introduce`, `address`)
- 운영 중단 상태 필터링 등 복합 조건 검색

### 🔧 향후 계획
- 🔄 **한글 → 영문 검색 자동 대응 (예: "뉴진스" → "NewJeans")**
    - 아직 `normalizeKeyword()`와 같은 한-영 매핑 로직은 미도입
    - 추후 사전 기반 또는 ML 기반 변환 로직을 도입하여 사용자 검색 경험 개선 예정
- 🔎 **검색어 추천, 자동완성, 인기 검색어 기능** 도입
- 📊 **Kibana 연동을 통한 검색 트래픽 시각화 및 인사이트 분석**

---

## 🛠 기술 스택

- Elasticsearch 8.x
- Java 17, Spring Boot 3.x
- Elasticsearch Java Client (`co.elastic.clients:elasticsearch-java`)
- Nori 분석기 (한글 형태소 분석기)
- Kibana (검색 트래픽 분석 및 시각화)
